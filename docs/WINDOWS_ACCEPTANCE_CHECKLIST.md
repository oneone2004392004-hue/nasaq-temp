# قائمة قبول Windows — Nasaq POS 1.0.2

نفّذ على أجهزة اختبار منفصلة، لا على قاعدة إنتاج. سجّل Windows build، نوع الطابعة، إصدار WebView2، وقت الاختبار، والنتيجة. أوقف الاختبار عند فقد بيانات أو فساد قاعدة.

| الخطوة | النتيجة المتوقعة | ناجح؟ | ملاحظات |
|---|---|---|---|
| تثبيت نظيف على Windows 10 | يثبت NSIS، يفتح التطبيق، ويُنشئ قاعدة سليمة في `%APPDATA%` | ☐ | سجّل إصدار Windows ونتيجة `integrity_check` |
| تثبيت نظيف على Windows 11 | يثبت NSIS ويفتح التطبيق دون أخطاء | ☐ | سجّل إصدار Windows |
| تثبيت على جهاز بلا WebView2 | يثبت WebView2 أو يعرض رسالة عربية واضحة وخطوة استعادة مدعومة؛ لا يتعطل بصمت | ☐ | اختبر جهازاً افتراضياً نظيفاً |
| تفعيل جديد | ينجح التفعيل وتُحفظ الحالة في AppData | ☐ | سجّل إعادة تشغيل واحدة |
| مسح بيانات WebView ثم إعادة التشغيل | تبقى حالة التفعيل؛ لا يعتمد التفعيل على localStorage وحده | ☐ | امسح بيانات WebView فقط، لا AppData للتطبيق |
| طابعة USB — CP864 | تطبع صفحة الاختبار؛ «إجمالي» و«إلغاء» عربيان صحيحان | ☐ | سجّل الطراز ورقم code page |
| طابعة USB — WPC1256 | تطبع صفحة الاختبار؛ «إجمالي» و«إلغاء» عربيان صحيحان | ☐ | سجّل الطراز ورقم code page |
| طابعة USB — Raster | يطبع raster عند تعذر code page، دون قلب أو قطع للنص العربي | ☐ | سجّل الإعداد والدقة |
| طابعة شبكية | تنجح الطباعة، ثم يظهر خطأ واضح عند فصل الشبكة أثناءها | ☐ | أعد الاتصال وتحقق من إعادة الطباعة دون تكرار مالي |
| درج نقدية | يفتح الدرج من عملية مخوّلة فقط | ☐ | سجّل نوع الاتصال وإذن المستخدم |
| قارئ باركود | يقرأ الباركود ويختار المنتج الصحيح مرة واحدة | ☐ | جرّب باركود معروفاً ومجهولاً |
| بيع عند 00:30 و01:30 والتقارير | يرتبط كل بيع باليوم والوردية المقصودين؛ التقارير تطابق فواتير اليوم | ☐ | غيّر التاريخ في بيئة اختبار معزولة |
| إنهاء العملية أثناء البيع (End Task) | بعد التشغيل، قاعدة البيانات تجتاز `PRAGMA integrity_check`؛ الطلب إما كامل أو غير موجود، بلا خصم مزدوج | ☐ | استخدم قاعدة اختبار ولقطة قبل البيع |
| Reload عبر Ctrl+R أثناء البيع | الواجهة تستعيد حالة متسقة؛ يمكن تنفيذ بيع جديد دون تكرار البيع السابق | ☐ | لا تستخدم عملية مالية حقيقية أثناء reload |
| نسخ احتياطي ثم استعادة ثم بيع | تستعاد البيانات؛ البيع التالي يعمل ويحدّث المخزون مرة واحدة | ☐ | احتفظ بنسخة قبل الاستعادة |
| استعادة ملف تالف | تُرفض الاستعادة؛ تبقى القاعدة الأصلية قابلة للفتح وسليمة | ☐ | احتفظ بالملف التالف للاختبار فقط |
| مرتجع نقدي بعد إغلاق الوردية الأصلية | المرتجع يتطلب الإذن والتأكيد المناسبين؛ الرصيد والسجل والتدقيق صحيحون | ☐ | افحص جداول return, payment, audit |
| أداء 5000 فاتورة | إنشاء/عرض/بحث لا يعلق ولا يفقد بيانات؛ سجّل الزمن والذاكرة | ☐ | سجّل الجهاز، مدة الإدخال، ومدة فتح التقارير |
| تبديل المستخدمين وفك القفل | تتغير الصلاحيات حسب DB؛ العدّاد والقفل يبقيان بعد إعادة التشغيل | ☐ | جرّب cashier ثم manager ثم admin |
| ترقية من 1.0.2 | تحفظ بيانات النسخة السابقة؛ تكتمل migration؛ `integrity_check` يمر | ☐ | خذ backup قبل الترقية وسجّل migration IDs |
